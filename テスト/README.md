二進数バトル（`../screen.html`）を**ブラウザを開かずに**確かめるための道具一式。

## 使い方

`二進数バトル` フォルダで、次を実行する（Node.js が必要）。

```bash
node テスト/run-all.js
```

これで5本のテストが全部走る。最後に「✅ 全テスト合格」と出れば問題なし。
**コードをいじったら、まずこれを走らせる。**

個別に走らせたいときは、ファイル名を直接指定する。

```bash
node テスト/test5-modes.js
```

シミュレーション（時間がかかる。数十秒〜数分）はこちら。

```bash
node テスト/sim1-balance.js
```

## 仕組み：偽物のDOMを渡す

`screen.html` は `document.getElementById("board")` を使っている。
この `document` は**ブラウザが用意してくれる箱**で、Node には存在しない。

そこで、**同じ形の偽物を自分で作って渡す**（`common.js`）。

```javascript
const els = {};
const el = id => (els[id] = els[id] || {
  innerHTML: "", textContent: "", disabled: false, className: ""
});

vm.runInNewContext(readScript() + testCode, {
  document: { getElementById: el },   // ← 偽物
  console: console,
  el: el,
});
```

`el("board")` が返すのは**ただのオブジェクト**で、本物のHTML要素ではない。
でも `screen.html` 側は `document.getElementById("board").innerHTML = html` を実行できる。
**書き込む先が本物かどうかを、コードは区別できない**から。

舞台の書き割りと同じ。本物の家でなくても、役者は「ドアを開ける」演技ができる。
そしてあとから `el("board").innerHTML` を覗けば、何を書き込んだかが全部読める。

**この方式なら `screen.html` を1文字も変えずにテストできる。**
テスト用のコードを本体に混ぜると本体が汚れるうえ、
「テストのときだけ通る道」ができてバグの温床になる。

## 使えるようになる技

テストの中では、ゲームの変数や関数をそのまま触れる。

```javascript
person2.right = 31;         // 「片手だけ死んだ状態」を1行で作れる
turnCount = MAX_TURNS - 2;  // 「あと2手で引き分け」まで一瞬で進める
setMode("normal");          // モードを切り替える
```

ブラウザで同じ状態を作るには何手も打つ必要がある。**これがテストの一番おいしいところ。**

小道具（`common.js` の PRELUDE で用意してある）：

| 名前 | 使い方 |
|---|---|
| `ok(条件, 説明)` | 条件が true なら OK、false なら ★NG と表示して失敗を数える |
| `section(見出し)` | 見出しを出す |
| `fingersUp(n)` | n のとき指が何本立つかを数える |
| `buttonStates()` | 4つのボタンの状態を `"有効 無効 有効 有効"` の形で返す |
| `el(id)` | 画面に何が書き込まれたかを覗く |
| `runTimers()` | 予約された `setTimeout` を今すぐ全部発火する（CPUの手を待たずに進める） |
| `pendingTimers()` | 予約が何件たまっているか |

**`setTimeout` も偽物にしてある。**本物は「700ミリ秒待つ」が、テストの偽物は
**予約を溜めるだけ**で待たない。`runTimers()` を呼んだ瞬間に走る。
おかげで「CPUが打つ前の状態」と「打った後の状態」を、待ち時間ゼロで別々に確かめられる。

## シミュレーションで気をつけること

今日（2026-07-27）実際にやらかしたか、防いだもの。

| # | 落とし穴 | 対策 |
|---|---|---|
| 1 | シミュレーターが本物とズレている | **全パターン突き合わせて0件を確認してから走らせる**（`verify()`）。これをやらないと「シミュレーターのバグ」を「ゲームの性質」と勘違いする |
| 2 | 打ち切りを1つしか試さない | 「長いだけ」と「本当に終わらない」を混同する。**打ち切りを100倍にして2回測る** |
| 3 | 1つの打ち手だけで結論を出す | 初心者と上級者で逆の結論が出ることがある（分割ルールが実例） |
| 4 | 仮説に合うデータだけ見る | 素数仮説を立てたが、データが否定したので捨てた |
| 5 | 平均だけ見る | 平均は極端な値に引っ張られる。**中央値と上位5%も並べる** |


**④が肝。作る前に測る。**
